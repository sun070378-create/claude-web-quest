# 第 21 關：抓蟲大作戰 🐛

> 第四章開始！這一章要學「真正在寫網頁的人每天都在用」的技能。第一個：**找出程式哪裡壞了**。

程式出錯叫做 **bug**（蟲），找蟲、修蟲叫做 **debug**（除錯）。
就算是寫了十年程式的工程師，每天也花很多時間在 debug。重點不是不寫錯，而是**會找錯**。

## 這關會學到

- 看懂主控台（Console）的錯誤訊息
- 用 `console.log` 偷看變數的值
- 兩種蟲：**會報錯的**，和**不會報錯、但結果是錯的**

## 觀念小抄

### 1. 先看主控台

按 `F12` →「Console（主控台）」。紅色的就是錯誤，最右邊會寫**檔名和第幾行**，點下去會直接跳到那一行。

常見的錯誤訊息：

| 錯誤訊息 | 意思 |
|------|------|
| `Cannot read properties of null` 或 `Cannot set properties of null` | 你想用的東西是 `null`，通常是 `querySelector` 沒找到（名字打錯？） |
| `xxx is not defined` | 用了一個不存在的變數或函式（拼錯？忘了宣告？） |
| `Unexpected token` | 語法錯誤：少了括號、引號、逗號 |

> ⚠️ 只要有一個錯誤，**錯誤後面的程式全部都不會執行**。所以要從第一個紅字開始修。

### 2. 沒有錯誤，但結果不對？用 console.log

在懷疑的地方加一行，把變數印出來：

```js
console.log("小計是", subtotal);
console.log("運費是", shipping, typeof shipping);   // typeof 會告訴你它是 number（數字）還是 string（文字）
```

重新整理，看主控台印出了什麼，跟你想的一樣嗎？找到蟲之後，記得把 `console.log` 刪掉。

### 3. 按了沒反應？

先在事件裡加 `console.log("有按到")`：

- 主控台沒印出來 → 事件根本沒有觸發（事件名稱拼錯？綁錯元素？）
- 有印出來 → 事件有觸發，問題在後面的程式

## 額外挑戰

- 在主控台直接輸入 `subtotal` 按 Enter，為什麼會說 `not defined`？（提示：它是寫在函式「裡面」的變數）
- 試試開發者工具的「Sources（來源）」分頁：在行號上點一下設「中斷點」，程式跑到那裡會暫停，可以一步一步看變數怎麼變化。
